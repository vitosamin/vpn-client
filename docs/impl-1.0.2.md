# Отчёт: Vitosamin 1.0.2 — экран, переключение серверов, обновления

Дата: 2026-11-01. Ветка `main`, версия `1.0.2+3`, подпись `CN=Vitosamin`.

Собрано вручную (Flutter 3.38.5, JDK 17, SDK 36, NDK 28.2), проверено
`flutter analyze` (чисто), тестами `test/features/proxy` и
`test/features/app_update` (55 зелёных) и подписью APK. Публикация релиза —
через GitHub Actions по тегу (см. [RELEASING.md](RELEASING.md)).

## 1. Главный экран: вместо белого круга — кнопка

**Проблема.** В hero-карточке стояла кнопка Hiddify «eclipse»: белый диск ~148 px
с белой монограммой сверху — на белом диске монограмма не видна, оставался
пустой белый круг, который и занимал пол-экрана.

**Решение.** `ConnectionButton` получил вариант `ConnectionButtonVariant.pill`
(`lib/features/home/widget/connection_button.dart`), hero использует его
(`lib/features/home/widget/home_hero.dart`):

- широкая кнопка 58 px, радиус 18, градиент по состоянию: синий — выключено и
  подключение, зелёный — подключено, янтарный — подключена цепочка с проблемой,
  красный — ошибка, спиннер внутри при переходных состояниях;
- подпись — глагол: «Подключить» / «Отключить» / «Отключение…» / «Повторить»,
  строки уже есть в переводах (`connection.connect`/`disconnect`/…);
- при ошибке под кнопкой появляется «Подробнее» — старый диалог ошибки никуда
  не делся;
- у статуса убран дубль «Нажмите для подключения» (кнопка и так говорит, что
  делать), зато у подключённого состояния появилась подпись «Защищённое
  соединение»;
- круглая кнопка и painter остались для других мест, hero их больше не рисует.

Скриншоты: [home-disconnected.png](screenshots/home-disconnected.png),
[home-connected.png](screenshots/home-connected.png) (рендер реального виджета
в тесте, ru-локаль, тёмная тема).

## 2. Переключение серверов: выбранный держится

**Проблема.** Приложение могло «перетягивать» сервер с ядром. Автоселект угадывал
ручной выбор эвристикой: если выбранный ядром сервер расходился с его собственным
дольше 8 секунд, это считалось выбором пользователя. Ядро отдаёт список с
задержкой, и его собственный поздний отчёт выглядел как «пользователь выбрал
другой сервер»: автоселект запоминал чужой выбор, потом видел, что тот мёртв, и
переключался снова — отсюда серия переключений.

**Решение.**

- `lib/features/proxy/active/proxy_pick_signal.dart` — явный сигнал из списка
  прокси: тап по серверу → `pickedServer`, тап по группе или «самый быстрый» →
  `pickedGroup`. Пишут его `proxies_overview_notifier.dart` и
  `active_proxy_notifier.dart` (`switchToFastest`).
- `priority_failover_notifier.dart` слушает только этот сигнал; эвристика
  `_reconcileCorePick` и сравнение с `mainOutboundsNotifierProvider` удалены.
- `priority_selector.dart`: пинг `0` — «ещё не измерено», а не «мёртв». Раньше
  три нуля подряд (а не таймауты) уже двигали трафик; теперь для смены нужны три
  **измеренных** таймаута (`>= ConnectionConst.maxDelay`), кулдаун 45 с, возврата
  на приоритетный сервер по-прежнему нет.
- Правила прежние: выбранный отвечает — не трогаем, даже если выше по списку
  есть живой или быстрый; умер — берём первый живой по порядку подписки; все
  мертвы — стоим на месте и один раз сообщаем «нет связи».

Тесты: `test/features/proxy/priority_selector_test.dart` (23, включая новый
сценарий «неизмеренный пинг не считается падением»).

## 3. Обновления с телефона через GitHub Releases

- `Release.allowCustomUpdateChecker` теперь `true` (было `false` — обновления
  были выключены, чтобы не предлагать релизы Hiddify).
- `AppUpdateNotifier.check({automatic})` — при старте не чаще раза в 12 часов,
  из «О приложении» — по кнопке; ошибки автоматической проверки молчат.
- `GithubReleaseParser` на Android берёт из ассетов релиза APK: universal →
  обычный → arm64; на остальных платформах остаётся страница релиза. Кнопка
  «Обновить» в диалоге скачивает APK прямо в браузер.
- `UpgradeAlert` (апстримный appcast с фидом Hiddify) убран из дерева виджетов:
  он дублировал проверку и смотрел не туда.
- `.github/workflows/release-apk.yml` — по тегу `v*` собирает universal и arm64
  APK, подписывает keystore из секретов, проверяет `apksigner` и публикует
  релиз с `SHA256SUMS.txt`. Апстримные workflow удалены, чтобы их релизы и
  проверки не запускались в форке.

Репозиторий обновлений зашит в `lib/core/model/constants.dart`
(`vitosamin/vpn-client`).

## 4. Что осталось

- Форк на GitHub создаёт человек: токен на машине не имеет права создавать
  репозитории. После этого `publish-vitosamin.sh` переименует форк в
  `vpn-client`, запушит `main`, выставит секреты и тег `v1.0.2`.
- Проверка на телефоне: установка 1.0.2 поверх 1.0.1, вид главного экрана,
  отсутствие «дребезга» серверов, обновление с релиза.
