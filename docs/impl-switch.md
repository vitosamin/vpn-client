# Переключение серверов только при недоступности — отчёт

Дата: 2026-10-31. Задача: shared task board, task-10.
Ветка: `feat/switch-only-dead`, worktree `/root/MyHome/vpn-client/app-switch`
(от `main` = `7a37aba`, где уже смержен автоселект `feat/priority-failover`).
В `main` не мержила; `app/` и другие worktree не трогала; `hiddify-core` не патчила;
UI главной страницы (её параллельно правит другой разработчик) не меняла.

## 1. Что изменилось

Владелец протестировал APK из прошлой задачи: серверы переключались слишком часто.
Причина — логика автоматического возврата: приоритетный сервер отвечал 3 оценки подряд,
и через 60 с трафик возвращался на него. Убрала возврат полностью.

**Новая логика (только по недоступности):**

| Параметр | Было | Стало |
|---|---|---|
| Автоматический возврат на приоритетный | 3 оценки + 60 с → возврат | **убран полностью** |
| Порог недоступности активного | 2 неудачные оценки (~30 с) | **3 оценки подряд (~45 с)** |
| Решение о переключении | по приоритету и по «восстановлению» | **только когда активный недоступен**; пинг — только «жив/мёртв», скорости не сравниваются |
| Цель переключения | первый живой по приоритету | первый живой по порядку подписки (умерший сам не «жив»); если живых нет — остаёмся на месте |
| Кулдаун между переключениями | 20 с | **45 с** (в диапазоне 30–60 с) |
| Все серверы недоступны | оставались на месте | остаёмся на месте + один тост «нет связи» за период простоя |
| Ручной выбор | уважается | уважается (то же поведение) |
| Переподключение/смена профиля | сброс → первый живой | без изменений |

То есть после временного падения приоритетного сервера трафик остаётся на резервном до
конца соединения — «туда-обратно» больше не прыгает. Возврат к первому по приоритету
происходит только при новом подключении (переподключение, смена профиля), как и просил
владелец.

**Прочее поведение без изменений:** после `Connected` выбирается первый живой по порядку
подписки; ручной сервер не заменяется, пока отвечает (фейловер с него работает); выбор
группы/«самый быстрый» приостанавливает автоселект до переподключения; `url-test-interval`
остаётся 2 мин; активный сервер пингуется каждые 15 с.

**Пробы.** Раньше второй пробой пинговался «приоритетный сервер выше активного» — это было
нужно только для возврата. Теперь пингуется активный сервер + один другой сервер по кругу,
чтобы к моменту падения активного знать, кто из остальных жив (переключение не «слепое»).
Мониторинг ядра по-прежнему обновляет все пинги каждые 2 мин.

## 4. Риски и ограничения

1. **Реакция на падение — ~45 с** (3 оценки по 15 с) плюс время `SelectOutbound`. Это
   осознанный компромисс: короче — снова начнутся дёргания на кратковременных потерях
   пакетов, на что жаловался владелец.
2. **Возврата на приоритетный сервер нет вообще**, пока соединение не переподключится
   (или не сменится профиль). Так и задумано, но если приоритетный сервер «моргнул» на
   минуту, весь остаток сессии трафик идёт через резервный. Это ожидаемо по требованию;
   если понадобится «мягкий» возврат — только по явному запросу, с длинным окном стабильности.
3. **Когда мертвы все** — трафик остаётся на последнем выбранном (мёртвом) сервере и не
   метается. Ядро в этот момент само рапортует «нет соединения» (его состояние считается по
   группе `lowest`), плюс один тост «нет доступных прокси» за период простоя. Когда любой
   сервер оживёт (проба/мониторинг), переключение произойдёт после кулдауна.
4. **Кулдаун 45 с** может задержать второе переключение, если и резервный сервер умер сразу:
   суммарно до ~45 с (порог) + остаток кулдауна. Выбрано, чтобы не было серии быстрых
   переключений; при необходимости легко подкрутить константу.
5. **Проба второго сервера каждые 15 с** — небольшой дополнительный трафик/батарея
   (generate_204). Интервал не настраивается, как и раньше.
6. **На реальном телефоне в этой сессии не проверялось** (устройства/эмулятора нет):
   проверены код, analyze, unit-тесты и сборка APK. Нужен прогон владельцем: сервер с
   заведомо мёртвым первым и «моргающим» вторым должен дать одно переключение и никаких
   возвратов.
7. **Ручной выбор** определяется прежней эвристикой (расхождение с нашим выбором позже 8 с
   после переключения); редкое ложное срабатывание приостанавливает автоселект до
   переподключения — безопасное направление.
8. **UI главной** не трогала по указанию (параллельная правка другим разработчиком).
   Бейдж «фейловер» показывается, когда активный сервер не первый по подписке, в том числе
   если первый был мёртв изначально. Если другой разработчик переделывает карточку, стоит
   согласовать отображение бейджа.
9. Лиду: ветка `feat/switch-only-dead` готова к ревью/мержу в `main` (база — `7a37aba`).
   Перед выпуском — прогон на телефоне по сценарию из п. 6.
