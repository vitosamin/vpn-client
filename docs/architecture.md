## Поток активации

1. Пользователь оплачивает доступ (сейчас — вручную/через бота, автоматизация
   позже).
2. Бот (или админ) создаёт код: `POST /v1/codes` → одноразовый код, привязанный
   к клиенту 3x-ui (UUID/email), сроку и объёму.
3. Пользователь открывает приложение и вводит код (или переходит по
   `vpn://activate?code=...`).
4. Приложение: `POST /v1/activate {code, device_id}`.
5. API проверяет код (TTL, использование, лимит попыток), создаёт клиента в
   нужном inbound 3x-ui (если ещё не создан) и возвращает `sub_url` — стандартную
   подписку 3x-ui `/sub/<subId>`.
6. Приложение добавляет профиль, обновляет подписку и поднимает туннель.
   Заголовок `subscription-userinfo` (3x-ui) даёт срок и остаток трафика для
   экрана статуса.

Одноразовость: код можно обменять только один раз на одно устройство; повторный
ввод на том же `device_id` — идемпотентно возвращает ту же подписку (чтобы не
терять доступ после переустановки, пока код не истёк).

## Клиент

- Форк Hiddify: Flutter UI + ядро sing-box (TUN).
- Подписка: стандартный sub-URL 3x-ui (base64 vless-ссылки). Поддерживаем
  несколько серверов в подписке — это и есть основа автоселекта.
- Автоселект: при старте — health-check по списку, выбираем **первый живой по
  приоритету** (приоритет — порядок серверов в подписке/настройке), при падении
  — переключение на следующий; периодический возврат на приоритетный.
  (В Hiddify штатно — urltest по пингу; дорабатываем под приоритеты.)
- Гео: правила sing-box `geoip-ru` + `geosite-category-ru` (и списки
  itdoginfo/allow-domains) → `direct`; всё остальное → прокси. Списки
  обновляются, чтобы не ломаться со временем.
- AWG (v2): отдельный транспорт, серверный `amneziawg` на VPS; в клиенте —
  userspace `amneziawg-go` (MIT) под тот же TUN, переключение VLESS ⇄ AWG.

## Серверы

- 3x-ui: `msk.vitosamintm.ru` (VLESS/Reality, цепочка на PL, WARP-резерв) и
  `pl.vitosamintm.ru` — см. `vless-msk/README.md`.
- Подписка выдаётся панелью; наш API только создаёт клиентов и хранит коды
  активации.
- RU-трафик не гоняем через VPN: банки/Госуслуги/маркетплейсы не любят
  иностранный IP.

## Безопасность

- Коды активации — криптостойкие, с TTL и лимитом попыток; в базе — хэш.
- API активации — только HTTPS, Bearer-токен для админ-эндпоинтов.
- В приложении не храним пароли панели, только sub-ссылку.
- Логи без секретов; на серверах — обычные меры (fail2ban, только нужные порты).
