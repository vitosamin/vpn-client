## 1. В чём была проблема

Правило «обход региона» включено по умолчанию, регион по умолчанию — `ru`, но само правило было
пустым: оно ссылалось на два remote-набора с GitHub
(`lib/features/route_rules/notifier/rules_notifier.dart:19,75`):

```
https://raw.githubusercontent.com/hiddify/hiddify-geo/rule-set/country/geosite-{region}.srs
https://raw.githubusercontent.com/hiddify/hiddify-geo/rule-set/country/geoip-{region}.srs
```

Ядро скачивает их через туннель (`DownloadDetour: "select"`) и уже после старта (в форке
hiddify-sing-box начальная загрузка отключена, обновление — по 10-секундному тикеру). То есть
до первой загрузки правило не матчит ничего; если GitHub в этот момент недоступен, RU-сайты
уходят в прокси, пока набор не скачается. Владелец требует, чтобы гео было встроено в APK и
RU→direct работал сразу, без сети и без GitHub.

## 2. Что выяснено про ядро (почему «локальный путь» сам по себе не работает)

Правило приложения (`Rule`) передаётся ядру как proto `RouteRule`; единственное, что ядро берёт
из него про наборы, — `rule_sets: repeated string` (URL-ы). Дальше
`hiddify-core/v2/config/route_rules.go`:

- `buildAppRouteRules` (:53) обходит включённые правила приложения;
- `add` вытаскивает URL-ы и зовёт `ruleSet(url)`;
- `ruleSet(url)` (:232) **всегда** создаёт `option.RuleSet` с `Type: C.RuleSetTypeRemote` (:265),
  `Format` — по расширению (`.srs` → binary), `RemoteOptions.URL = url`,
  `DownloadDetour: OutboundSelectTag`;
- путь/тип «local» в этом коде не выбирается никогда.

При этом сам sing-box 1.13 локальные наборы умеет (`option.RuleSet` с `LocalRuleSet{Path}`,
`constant.RuleSetTypeLocal`), и hiddify-sing-box это поддерживает. Но в модели `Rule` приложения
и в билдере ядра нет поля, через которое можно передать файл: строка `rule_sets` — это URL, и
всё, что в неё положить, ядро обернёт в remote-набор (HTTP-клиент не откроет `file://`).

Отдельная legacy-ветка ядра (когда `RouteRule` не задан: `!useAppRules` в `builder.go:770+`)
добавляет к remote-наборам правило `domain_suffix: .ru` — но приложение всегда шлёт `RouteRule`,
так что эта ветка не используется и от неё ничего не зависит.

**Вывод.** Вариант A из задачи (local `.srs` в ассетах) и вариант B в исходном виде (скопировать
`.srs` в рабочую директорию ядра и указать локальный путь) без патча ядра невозможны: ядро
сделает из переданной строки remote-набор. Патчить `hiddify-core` запрещено, поэтому реализован
**вариант C — inline-списки из ассетов**.

Рассматривала и «запасной» вариант с предварительно заполненным кэшем наборов: в форке
hiddify-sing-box remote-набор грузится из cache DB (`<workingDir>/data/clash.db`, bbolt) до
старта, значит можно было бы возить предсобранную `clash.db`. Отбросила: бинарный артефакт в
git, путь и само включение кэша зависят от настройки Clash API (пользователь может её выключить),
ошибка чтения кэша в форке фатальна для старта VPN, проверить без устройства нельзя, и правило в
конфиге всё равно остаётся remote — то есть не выполняет требование «правило реально присутствует
в сгенерированном конфиге».

## 3. Что сделано (вариант C)

**Списки в APK.** `assets/geo/` — три текстовых файла, по одному элементу на строку, из наборов
hiddify-geo (`geosite-ru.srs`, `geoip-ru.srs`, это те же данные, что скачивало приложение):

| Файл | Содержимое | Элементов | Размер |
|---|---|---|---|
| `assets/geo/ru_domain.txt` | точные домены `geosite-ru` | 236 | 5 188 Б |
| `assets/geo/ru_domain_suffix.txt` | суффиксы доменов `geosite-ru` | 1 917 | 23 960 Б |
| `assets/geo/ru_ip_cidr.txt` | CIDR-ы `geoip-ru` | 25 024 | 443 295 Б |

Обновляются скриптом `scripts/update-geo-rules.sh` (скачивает `.srs`, проверяет HTTP 200 и
размер, распаковывает `sing-box rule-set decompile`, раскладывает в текст; `--check` сверяет
без записи). Источники, размеры и sha256 зафиксированы в `assets/geo/README.md`. Для работы
приложения скрипт не нужен — он только для обновления списков.

**Правило.** `BuiltinRule.bypassRegion.rule(region)` для региона `ru` при загруженных ассетах
строит обычное правило `outbound: direct` с `domains` (236) и `domainSuffixes` (1917), **без**
`ruleSets` — то есть без единого похода в сеть. Для остальных регионов поведение не изменилось:
remote-наборы с `{region}`, как и было (иначе был бы регресс для ir/cn/tr/…). Если ассеты не
загрузились (не должно случаться), правило тоже откатывается на remote-набор.

**Разделение на два правила в конфиге (важно).** Ядро добавляет DNS-правило «резолвить прямым
DNS» только правилу, у которого нет IP-условий (`addDNSRule`, `route_rules.go:174`: «Only rules
that match on names alone get one: a port, network, protocol or IP condition can't be checked on a
DNS query»). Если положить CIDR-ы в то же правило, RU-домены перестали бы резолвиться прямым DNS
(резолв ушёл бы через прокси — а RU-сайты часто отдают разные ответы зарубежным резолверам).
Поэтому `effectiveRouteRules` (см. таблицу файлов) перед отправкой в ядро делит правило региона
на два с тем же outbound: правило имён (236 доменов + 1917 суффиксов) и правило диапазонов
(25 024 CIDR-а). Для sing-box это эквивалентно одному правилу: доменное условие и IP-условие
складываются по ИЛИ (домены кладутся в `destinationAddressItems`, CIDR-ы — в
`destinationIPCIDRItems`, финальная проверка принимает совпадение любого из них). В
сгенерированном конфиге видно, что у правила имён появилось DNS-правило с
`dns-direct-group` — резолв остаётся прямым.

В списке правил приложения (и в сохранённом `route_rule.proto`) остаётся **одно** правило с
доменами: IP-диапазоны добавляются там, где строится конфиг ядра, поэтому сохранение/экспорт
списка не раздумывается на 25 тысяч строк, а поведение «выключил правило — выключились и
диапазоны» сохраняется.

**Загрузка.** `BundledGeoRules.load()` вызывается в `lazyBootstrap` (до инициализации ядра и
`runApp`) через `_safeInit`: 461 КБ текста читаются один раз; ошибка чтения не валит старт, а
оставляет правило на remote-наборе.

**Онбординг.** Регион по умолчанию уже был `ru` (`config_option_repository.dart:39`), оба
встроенных правила включены (`bypassRegion`, `bypassLan`). Но интро перетирало регион на
`Other`, когда тип таймзоны не давал страны: `RegionDetector.detect()` возвращал `US`, а тот
маппился в `Region.other` — регион-правило при этом вообще убирается из списка. Теперь
`detect()` возвращает `null`, если зона не называет страну (`UTC`, пустая, неизвестная), и интро
оставляет дефолт `ru`; сетевой фолбэк на `api.ip.sb` остался, явно определённая зарубежная
страна по-прежнему даёт `Other`.

## 6. Как обновлять списки

```bash
scripts/update-geo-rules.sh          # скачать .srs, пересобрать assets/geo/*.txt
scripts/update-geo-rules.sh --check  # только сверить с свежим скачиванием (exit 1, если устарело)
```

Нужны `bash`, `curl`, `python3` и бинарник `sing-box` (скрипт сам скачает релиз 1.13.0, если его
нет на PATH; можно указать `SING_BOX=/path/to/sing-box`). После обновления — `flutter test
test/features/route_rules` и новая сборка APK: списки лежат в APK, поэтому пользователи получают
обновление вместе с версией приложения. Это осознанный размен за работу без сети.

## 7. Риски и ограничения

1. **Главное ограничение — в ядре.** `route_rules.go:232` принимает только URL и всегда строит
   remote-набор (:265); local rule-set (`option.RuleSet` с `LocalRuleSet`, sing-box это умеет)
   через модель `Rule` не передать. Поэтому списки пришлось «инлайнить» в правило. Предложение
   для hiddify-core (по правилам репозитория — сообщить о корневой причине, а не прятать её в
   приложении): поддержать в `ruleSet()` либо не-http строку как локальный путь
   (`C.RuleSetTypeLocal` + `LocalOptions{Path}`), либо добавить в proto `Rule` поле типа набора.
   Тогда можно возить `.srs` (15 684 + 104 905 Б) и не раздувать конфиг; в приложении для этого
   одно место — `BuiltinRule.rule` + `effectiveRouteRules`.
2. **Размер конфига и передачи.** `route-rule` для `ru` — 528 КБ JSON; он отправляется ядру при
   смене настроек/подключении, полный конфиг — 564 КБ, ядро строит его ~0,2 с (на телефоне
   дольше). Если на слабых устройствах это станет заметно, можно урезать: оставить inline только
   домены (29 КБ), а CIDR-ы вернуть в remote-набор/в отдельный кэш. Сейчас оба набора, как в
   штатном geosite+geoip.
3. **Правило в конфиге — два, в UI — одно.** Это следствие ограничения DNS (см. §3). Маршрутизация
   эквивалентна (домены ИЛИ диапазоны), DNS-поведение даже лучше, чем было бы с одним правилом.
   Если кто-то будет сравнивать список в UI с `route-rule` в конфиге — это объяснение.
4. **Другие регионы не трогала.** Для `ir/cn/tr/…` правило осталось remote-набором (иначе
   регресс), для них по-прежнему нужен прокси/GitHub, но это не дефолт и не задача.
5. **`Other`.** Ручной выбор «Other» (и сохранённый `other` у старых установок, которых старый
   онбординг ошибочно туда перевёл) по-прежнему убирает регион-правило — мы не перетираем
   пользовательский выбор. Миграцию для уже сохранённого `other` я не делала (это отдельное
   решение), новая установка и установка с неопределённой таймзоной теперь остаются на `ru`.
6. **На устройстве не проверено.** В этой среде нет Android-устройства/эмулятора: проверены
   сгенерированный ядром конфиг, unit/widget-тесты, analyze и сборка APK. Реальный трафик
   (RU-сайт идёт direct, зарубежный — через прокси) стоит проверить на телефоне при приёмке.
7. **Кэш remote-наборов** (альтернатива §2) остаётся возможным запасным путём, если появится
   требование не трогать формат правила, но он хуже по проверяемости и связан с настройкой
   Clash API.
